## A·输入类（RC64-RC66）· "用户给啥我照搬"

### A1·用户素材不加思考照搬整段

| 版本     | 翻车                              | 根因        | 规避（已焊 RC64）                                              |
| ------ | ------------------------------- | --------- | -------------------------------------------------------- |
| v1-v15 | 我把公众号/笔记/飞书文档整段贴进 prose，卡片变"文档" | 没拆散重组进结构件 | 拆→拣→重组：①按 s1-s5 打标 ②拣哪段进 HTML/哪进 md/哪丢弃 ③按 prose+结构件双轨重建 |

### A2·照搬书里原话进卡片 prose

| 版本      | 翻车                                                              | 根因                                     | 规避（RC65）                                        |
| ------- | --------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------- |
| v14-v20 | "用钱投资，而不是只消费"这种**完整原话**整段贴进 s5 prose，又把它放进 `.quote` 复抄一次 = 双重冗余 | 原话归宿应该是 md 镜像，卡片只保 `.quote` 一处 + 大白话解读 | **30 字规则**：书里原话超 30 字 → 不许动；只留 `.quote` + 大白话解读 |

### A3·照搬序言/译者注/不反常识发散 当核心

| 版本            | 翻车                    | 根因     | 规避（已焊 RC64）                                         |
| ------------- | --------------------- | ------ | --------------------------------------------------- |
| 进化心理学 v16-v18 | 中文版序言讲"贞洁观念"被误升 s4 核心 | 没做来源分层 | **来源分层铁律**：作者核心→s3/s4；序言/不反常识→不进核心（真反常识才进 s5 标注是延伸） |

### A4·热评漂移

| 版本 | 翻车                  | 根因    | 规避（RC64）                     |
| -- | ------------------- | ----- | ---------------------------- |
| 多书 | 把豆瓣热评"鸡汤化总结"伪装成作者观点 | 没忠实原意 | 热评总结只能讲读者原意；不漂移、不编造；不伪装成作者观点 |

**今后动笔流程**（输入闸门·D16 升级版）：

1. **看**：原书 chapterinfo/bestbookmarks/underlines + 微信读书 /review/list + 豆瓣热评
2. **辨**：六问全 YES 才动笔——「素材忠实反映书？」「不是照搬我给的？」「热评忠实不漂移？」「不是把序言当核心？」「不是把飘到海外当核心？」「结构是否重复合并过？」
3. **拆**：把"哪些进 HTML 哪段进 md"标出来
4. **重组**：写新内容，不是改原内容

### B3·派生样式覆写漏源头（v22）

| 版本  | 翻车                                 | 漏的 3 处                                                                                                                                                             | 规避（RC69）                                                                                                                 |         |            |
| --- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ------- | ---------- |
| v22 | 同一 `.vs.s4` 出来**虚线 / 实线 / 无框**三种边框 | ①父级 `.vs .col:first-child{border-right:2.5px dashed}` 漏 ②我自己加 `.vs.s4 .col.new{border:2px solid}` 多余 ③ mobile `.vs .col:first-child{border-bottom:2.5px dashed}` 漏 | **派生三铁律**：① grep 父级全部 CSS 列出 `border / border-方向 / background / border-radius` ② 逐条对照派生覆写 ③ 要么全清零要么全保留；写完 grep "border\\ | solid\\ | dashed" 验收 |

## D·以后拿到一本书怎么开干（SOP）

> **5 步实施·每步都有闸门**。

### 步骤 1·输入采齐（写前 30 分钟）

- [ ] 读原书 chapterinfo（关键章节）+ bestbookmarks（热门划线 10 条）+ 用户 underlines
- [ ] 微信读书 /review/list 看读者讨论
- [ ] 豆瓣热评 5-10 条（WebSearch）
- [ ] 用户已整理素材（优先直接用）

→ **闸门**：六问全 YES 才动笔（见 A 节末尾）

### 步骤 2·内容设计（30 分钟）

- [ ] 按 s1-s5 打标：定位/误区/破局/核心内容/核心价值——分别列 1-3 句
- [ ] 列出 s4 每张概念卡的递进：`chead → lead → 子机制 → 应用对照`
- [ ] 找出作者原话 3-5 处准备放 `.quote`（每张卡最多 1 个，不冗余）
- [ ] 相似主题主动合并（RC18）——相邻不机械扩

→ **闸门**：s4 有几张卡？核心机制 1+子机制 3-5+应用对照——否 → 重新设计

### 步骤 3·样式选用（10 分钟）

- [ ] 打开 `references/style-system.md` 第七节白名单
- [ ] 列出"核心内容用哪个 / 子机制用哪个 / 应用对照用哪个" ≥ 3 种
- [ ] 跨书有需要复用的：grep 源书 CSS 段+HTML 段**整段复制**（不是只搬 class 名）
- [ ] 任何白名单外新 class → 必须登记到第 4 节

→ **闸门**：每节至少 3 种不同结构件 / 派生 class 必走 RC69 三铁律

### 步骤 4·视觉交互（写时）

- [ ] L1 背景色分级先定（红色块 vs 灰色块数比）
- [ ] L2 边框样式补（实/虚/粗细）
- [ ] L3-L4 字号/圆角（最后）
- [ ] 全节"3 秒扫读"测试：截图后自问"读者能一眼知道哪个详读哪个略过吗？"
- [ ] 装饰物只用 1 处（标题红/正文黑是默认）

→ **闸门**：同节无 3 个以上红色块 / 主次至少 2 级

### 步骤 5·交付前（必跑）

- [ ] HTML 闸门：concept 数量 / .vs 数量 / .vs.s4 / .vs.old / 禁词 / 破折号 < 15
- [ ] MD 闸门：跟 HTML 关键术语一致（如"怎么不中招"/"认知误区"等）
- [ ] 派生 class 内 grep "border\\|solid\\|dashed\\|background" 验收
- [ ] graph.json 加节点（影响力 v22 任务内已加：1 book + 7 concept + 7 包含 links + 3 跨书相似）
- [ ] INDEX.md 同步更新（影响力原本就有，确认一致）
- [ ] present_files 给用户看

→ **闸门**：5 个闸门全过才 present_files，**绝不"先交付再说"**
