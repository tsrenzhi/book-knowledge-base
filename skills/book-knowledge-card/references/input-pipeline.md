# 写前输入闸门（强制 · 没真实输入不许动笔）

> **生效位阶**：本文件是 `book-knowledge-card` skill 的最高优先级前置纪律。任何一次"出书 / 改卡 / 写文案"动作，**必须先把以下四类真实输入采齐、读完、内化，才允许下笔**。用户 2026-08-18 第三次暴怒的核心："你要有正确的输入，才能去输出啊。你这些输入都没有，就胡编乱造怎么行？"——这句话是 RC16 的根。

## 一、为什么必须有这道闸门（RC16 根因）

| 根因 | 表现 | 用户原话 |
|---|---|---|
| **RC16 没把真实输入当输入** | 写前不读原书内容、不读真实读者评论、不读用户给的素材，全凭记忆 + AI 习惯生成 → 必然编造、必然浮夸、必然跑偏 | "写前你就应该先读这本书，在微信读书里先去读这本书的内容，同时去读用户的评论以及豆瓣里面相关的一些热评。你要有正确的输入，你才能去输出啊。" |
| **RC16.1 把用户素材当摆设** | 用户已经整理好的内容（笔记/公众号/口述）不采用或只当"点名对象"，自己另起一套 → 重复造、且和用户想讲的不一致 | "我也有可能给你提一些我思考过的内容，这些都是给你的输入啊，你要结合这些输入去写呀。你别上来就胡编乱造啊。" |
| **RC16.2 热评不忠实总结** | 网上扒的热评，要么直接当交付物贴出来、要么脱离原意"再创作"成自己的一套 → 等于编造 | "你从网上找的一些热评，可能因为各种原因没办法直接使用，那你就要做一定的总结。但是总结呢，你又不能太脱离原本的意思，你又开始编造了，那是不行的。" |
| **RC16.3 不拉用户自己的划线（2026-08-19 影响力暴怒新立）** | 用户明明在微信读书画了大量原文划线，我却只靠搜索记忆+热门划线写卡，不拉 `/book/bookmarklist`，用户划过的句子一条没用 → 写出来的是"我认为的重点"，不是"用户认可的重点" | "你有看我这个读书笔记里面的内容吗？微信读书里面。我记得我都画了很多好吗？我画了很多原文的内容，你都不看吗？你不知道基于原文去分析吗？" |
| **RC16.4 不核对版本（2026-08-19 影响力暴怒新立）** | 经典书做卡前没确认微信读书里是哪个版本，凭旧版知识写核心结构（影响力写成旧版 6 武器，实际全新升级版是 7 武器，新增「联盟」）→ 全书骨架错、被用户一眼看穿没读书 | "影响力最新的版本是7个武器好吗？7条原则好吗？你这个6条还是他妈的好多年前的。" |

**一句话铁律**：写之前先吃透"书里写了什么 + 真实读者怎么聊 + 用户已经想清楚了什么"，才可能写出不编、不浮、不跑的内容。**没有输入就动笔 = 违规。**

## 二、写前四类输入（顺序即优先级）

### ① 原书内容（必采 · 最高优先级输入）
- **目的**：知道作者到底讲了什么、结构是什么、哪些话最狠。这是内容的唯一真值源。
- **采集方式（微信读书，真实接口，禁编造）**：
  1. `bookId`：用户提供直接用；只给书名先 `/store/search` 解析。
  2. `/book/info` → `title/author/intro/newRating/newRatingCount/publishTime`（喂"书籍定位"与"值不值得读"）。
  3. `/book/chapterinfo` → 真实目录 `chapters[].{chapterUid,chapterIdx,title,level,wordCount}`；**章号/层级必须来自这里**，禁凭记忆。
  4. `/book/bestbookmarks` → 全站热门划线 `items[].{markText,totalCount,chapterUid}`（前 20，按 totalCount 排序）——这是"核心观点/最狠话"的真实燃料，映射到 chapterinfo 的 title 标出出自哪章。
  5. **`/book/bookmarklist` → 用户自己的划线（必采 · 最高优先级）**：用户画过的原文 `updated[].markText` 是**用户认可的骨架**，必须逐条读、按它组织核心内容；用户划线多的主题就是卡片要讲透的主题。配套 `/review/list/mine` 拉用户的想法/点评。
  6. **版本核对（必做 · 动笔前）**：`/store/search` 结果里确认用户读的是哪个版本（书名带"全新升级版/XX版"即不同版本）。经典书可能升级（影响力 1984 版 6 武器 → 全新升级版 7 武器，新增「联盟」），**卡片核心结构必须对齐用户实际在读的版本**，禁凭旧版知识写骨架。拿不准就问用户读的哪版。
- **铁律**：bestbookmarks 服务端固定只返前 20 条，不够用 `/book/info` 简介 + `/review/list` 补；**严禁谎称"全书重点都在这 20 条"**，拿不准明说"公开数据有限"。

### ② 微信读书公开点评（必采 · 真实读者人话）
- **目的**：看真实读者怎么聊这本书——哪些点最戳人、语气多接地气、我该把重心放哪。这是"人话"的活样本，对抗 AI 腔。
- **采集方式**：`/review/list`（bookId，reviewListType 0/1/2/3 按需；count 20，可翻页 maxIdx+synckey）。
- **用法**：只作**内部参考**，判断重心与语气；**绝不作为一节贴进卡片**（见「输入即素材，不是交付物」节）。

### ③ 豆瓣热评（必采 · 真实读者人话 · 跨平台对照）
- **目的**：跨平台验证"读者真正共鸣的点"，补微信读书评论的视角盲区；同样是对抗 AI 腔的人话样本。
- **采集方式**：
  - `WebSearch` 搜索：`"<书名> 戴维·巴斯 豆瓣 书评 热门短评"` 或 `"<书名> 豆瓣 短评"`。
  - `WebFetch` 抓真实页：`https://book.douban.com/subject/<douban_id>/comments`（短评）+ `/reviews`（长评）。**只取真实返回的内容，不推断、不编造评分/人数**。
- **用法**：同 ②，只作内部参考 + 人话校准，不当交付物。

### ④ 用户已整理好的素材（最高优先级 · 直接采用）
- **目的**：用户给的笔记/公众号/口述/已整理文档，是用户已经想清楚的内容，**是现成输入，不是待考证的外部资料**。
- **用法（RC16.1）**：
  - **用户已整理通顺/成稿的内容 → 基本直接用**：原样采用或最小改写，不另起一套、不"润色"成 AI 工整腔（见 D12 改稿最小手术铁律）。用户嗓音优先。
  - **用户给的是零散想法/口述 → 组织成用户自己的话**：补全场景但保留用户语气，不偷偷换成我的表达。
  - **融合规则**：用户素材 + 原书内容 + 真实读者评论，三者交叉核对——用户说的某点书里真有，就按用户的话讲、书里原话支撑；用户说的书里没有，只作"组织线索"，不凭空写成书里结论。

## 三、忠实总结规则（RC16.2 · 热评/豆瓣/网络素材怎么用）

> 用户原话："你从网上找的一些热评……可能没办法直接使用，那你就要做一定的总结。但是总结呢，你又不能太脱离原本的意思。"

1. **热评/豆瓣/网络素材 = 内部参考 + 人话样本**，不是可直接抄的交付物。需"做一定的总结"再内化进卡片。
2. **总结必须忠实原意，不漂移**：一条评论说"我们拥有石器时代的大脑却活在现代社会"，总结可以写成"读者普遍共鸣：人类心理机制是远古演化来的，跟不上现代社会节奏"——**这是同一意思的转述，合法**；但不能把它改成"作者说人类文明是错的""社会在退化"等原评没有的意思。
3. **禁止"再创作式总结"**：不把平实的读者感想，拔高/加油加醋成"深刻金句""反常识判断"塞进卡片——那是 RC4 造金句 + RC16.2 编造的合体。
4. **禁止把读者观点伪装成作者观点/自己的观点**：热评是"别人读后感的共鸣点"，只允许用来校准"我该把哪块讲透、语气多接地气"；卡片正文呈现的必须是书本身的内容重构。
5. **拿不准就明说**：某条热评/豆瓣观点我不确定书里是否支撑，**不硬塞进卡片**；宁可只用书里明确内容。

## 四、写前检查口令（每次动笔前默念，全 YES 才许写）

- [ ] ① 原书内容拿到了吗？（bookId / info / chapterinfo / bestbookmarks 真实返回，不是我编的）
- [ ] ①' **用户自己的划线拉了吗？**（`/book/bookmarklist` 必采，按用户划线组织核心内容；配套 `/review/list/mine`）
- [ ] ①'' **版本核对了吗？**（`/store/search` 确认用户读的版本，经典书升级版骨架可能变，如影响力 6→7 武器）
- [ ] ② 微信读书公开点评读了吗？（review/list 真实返回）
- [ ] ③ 豆瓣热评采了吗？（WebSearch/WebFetch 真实返回）
- [ ] ④ 用户给的素材用上了吗？（已整理→直接用；零散→组织成用户的话）
- [ ] 四类输入交叉核对过了吗？（用户说的书里真有？热评共鸣点书里能支撑？）
- [ ] 热评/豆瓣总结忠实原意了吗？（没漂移、没加油加醋、没伪装成作者观点）

**任一 NO → 先去采，不许动笔。** 这道闸门在"逻辑核查闸门（四）"和"硬闸门 grep（一）"之前——没输入，后面全白搭。

## 五、微信读书真实接口速查（curl 模板）

```bash
KEY=$(cat ~/.workbuddy/skills/wxds123__skillhub/.weread_key)
GATE="https://i.weread.qq.com/api/agent/gateway"
# ① 书籍信息
curl -s -X POST "$GATE" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_name":"/book/info","bookId":"<bookId>"}'
# ② 章节目录（真实章号/层级）
curl -s -X POST "$GATE" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_name":"/book/chapterinfo","bookId":"<bookId>"}'
# ③ 全站热门划线（前 20，真实 markText）
curl -s -X POST "$GATE" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_name":"/book/bestbookmarks","bookId":"<bookId>"}'
# ④ 公开点评（reviewListType: 0全部 1推荐 2差评 3最新）
curl -s -X POST "$GATE" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_name":"/review/list","bookId":"<bookId>","reviewListType":1,"count":20}'
# ⑤ 用户自己的划线（必采！按它组织核心内容）
curl -s -X POST "$GATE" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_name":"/book/bookmarklist","bookId":"<bookId>"}'
# ⑥ 用户自己的想法/点评
curl -s -X POST "$GATE" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"api_name":"/review/list/mine","bookid":"<bookId>"}'
# ⑦ 版本核对：先 /store/search 看结果里书名/版本，再定骨架
```

> bookId 来源：《进化心理学》= `3300174383`；其他书先 `/store/search` 解析。豆瓣 douban_id 用 WebSearch 查 `site:book.douban.com <书名>`。
