# 书籍知识卡片 · 内容与语言规范（详细版）

本文件是 `book-knowledge-card` 的执行细则：四块怎么写、不同书怎么灵活结构、哪些词不能用、以及只给书名时怎么从微信读书取真实重点。

---

## 〇、表达三铁律：区分文档 · 强化对比 · 连贯不跳

这三条是知识卡片区别于"文档"的根本，也是最常见的翻车点。每条都给判断标准和反例，写的时候逐条过。

### 铁律一：卡片是「重构」，不是「搬运」（身份）

- 同一份素材进卡片，要**重新组织**成网页结构（对比框 / 编号列表 / 标签 / 例子），不能把文档大段 prose 直接搬进 HTML。
- **判断标准**：截图看网页，3 秒内能说出"这个概念有几层、每层核心词是什么、跟谁对比、例子是什么"——说不出，就是还停留在文档态，要继续拆。
- **分工**：`《书名》.md` 镜像保留原话的**完整连贯**；卡片只负责"结构化呈现 + 显式化逻辑"。两者不互相替代，也互不污染。

### 铁律二：凡有对照，必用对比框（强化对比）

- 只要内容里出现 **旧认知 vs 新认知 / 现象 A vs 现象 B / 做法 A vs 做法 B / 改变前 vs 改变后**，强制用左右对比框 `.vs`，不要写成连续两段各说各的。
- **对比框写法纪律**：
 - 两栏**同结构**：同一套字段、同一描述顺序（如都按"看法 → 做法 → 结果"），不能左边写看法、右边写价格，对不齐读者就对比失败。
 - 必须点出**差异在哪、为什么关键**，不是把两点并排就完事。对比框下方跟一句"所以差别在…"。
 - 每一栏都要写完整因果链（特征 → 行为 → 后果），不能只有名词标签。比如写"金钱"不能只写"交换媒介、不增值、被稀释"，而要补成"追求金钱就是追求更多欠条，于是你只能为了钱不断工作，越忙越穷"。
 - 旧/错侧用深棕 `#6A6058` 描边，正确/新侧用红 `#E0432E` 强调，视觉上一眼分对错。
 - **「你以为 vs 真相」对比框：前提必须同一，只反驳结论，不能偷换概念。** 左栏「你以为」只放读者的**单一错觉**（同一前提 → 他以为的结论，例如"我无底线付出 → 他会感动更爱我"）；右栏「真相」直接推翻**同一个前提**该有的结论（"实际他不会感动，反而觉得你不会拒绝、把你好当理所当然"）。禁止把真相写进左栏、或左右各讲一套不相干的逻辑——那样前后是两套完全不同的因果，读着就是自相矛盾。
- **强对照禁止藏在 prose 里**：凡是出现"一种是 A，另一种是 B""A 能…，B 却只能…"这种并列解释，就属于强对照，必须拆出来做 `.vs` 对比框，不能让它混在正文段落中一笔带过。
- **反例（没对比，散讲）❌**：
 > "产品化就是录课卖很多人。一对一讲课时间会被锁死。"
 > 两点各说各的，读者要自己拼"所以呢"。
- **改顺（用对比框）✅**：
 > 左［出卖时间］一对一讲课，时间锁死在固定的几十人；右［产品化］把专长录成视频，同时卖给上万人，时间就解放了；下「差别在：前者卖一次赚一次，后者一次生产、可无限售卖」。
 > 读者一眼看到"同一种时间，两种命运"，转折和因果都显式了。
- **反例（对照藏在 prose 一句话里）❌**：
 > "斯密把劳动分成两种：一种是生产性劳动，能在产品上创造价值；另一种是非生产性劳动，一边干活一边就消耗掉了。"
 > 两句话把对照关系说完了，但读者看不到左右并置，差异被淹没在 prose 里。
- **改顺（拆出对比框）✅**：
 > 左［生产性劳动］制造东西、种地，活干完留下新价值，产出越滚越多；右［非生产性劳动］家仆、官吏服务，边干边消耗，财富不增长；下「所以国家变富，要把收入从非生产性挪到生产性」。
 > 对照关系被显式化，因果和后果一眼看清。

### 铁律三：连贯不跳，句子与板块都要有"筋"（转折 + 衔接词）

- **句子级（已有）**：每段至少带 所以 / 但是 / 而不是 / 比如 / 原因是 / 结果就是 / 也就是说 / 于是。
- **板块级（新增 · 最高频翻车点）**：上一个板块收尾，不能直接"咔"一下跳到下一个板块的新逻辑。要在**收尾或开头用一句承上启下**，明示两条逻辑怎么接：
 - 顺接："讲完作者怎么看 X，接下来自然要问：那普通人能拿来做什么？"
 - 转折："上面说的是原理，但落到现实，很多人卡在第一步——"
 - 悬念钩："讲到这你多半会想：道理都懂，可具体怎么开始？这正是下一节。"
- **板块内小标题之间**也要过渡：不能一个小标题讲完，下一个小标题凭空冒出新概念。新概念第一次出现，先在上一句铺垫"它指的是…"。
- **反例（跳脱）❌**：
 > "财富来源于社会分工。复利是世界第八大奇迹。人生要找杠杆。"
 > 三句毫无连接，读完像三个不认识的模块硬拼，中间一个连接词都没有。
- **改顺（连贯）✅**：
 > "财富来源于社会分工，分工越细效率越高；效率拉开差距之后，真正决定一个人能走多远的，其实是时间的复利——所以光会干活还不够，还要找对杠杆，让努力被放大。"
 > 用"效率拉开差距之后 → 其实 → 所以 → 还要"把三层逻辑串成一条线，读完不卡。
- **自检口诀**：朗读一遍，凡"咔"一下、要自己补主语 / 补"所以但是"才接得上的地方，就是跳脱，就地补过渡句。截图逐块看，块与块之间有没有"因此 / 但 / 讲到这"把人接住。

## 一、四块内容逐块写法

### ① 书籍定位（Hero）
- 第一行大字号书名（如《国富论》），第二行作者·出版年，第三行全称，最后一行**红色大字核心问题**（一个问题句，钩子感由它承担，不分行、不写副标题）。
- 只摆元信息 + 钩子，不在这里论证。
- 核心问题要"能戳中没读过的人"，例：国富论 → "一个国家，究竟靠什么变富？"

### ② 现实矛盾 / 旧观念（背景）
- 讲这本书诞生时，社会或学界卡在哪个**真实问题**上；旧思路落到现实的**具体恶果**（选择变少、价格更高、某行业被压制、普通人更穷）。
- 先把问题暴露足，再用"面对这些问题，作者才…"顺出作者；**禁**写"认知错误""错觉"这类抽象判定标签当因果枢纽。
- 若书本身是对两套旧观念的破局（如国富论 vs 重商/重农），用左右对比框 `.vs`（左旧观念+恶果 / 右另一旧观念+恶果），再一句点出共同盲区。

### ③ 作者的核心内容与方法论（重心）
- 全书逻辑主线。结构因书而异，常用四种：
 - **问题→解法**：作者针对背景里的真问题，给了哪几个解法（国富论用的就是"四支点"）。
 - **概念树**：一个核心概念拆成 N 个分支（用 `.stage` 概念树，core-node 在顶、vol-node 横排，箭头从 core 扇出到各 vol；节点只写"概念名+短标签"，具体解释放下方正文，框内不拥挤）。
 - **时间线 / 步骤**：方法论书、传记常用，按发展顺序讲。
 - **对比**：旧认知 vs 新认知、现象 A vs 现象 B。
- 每块配**一个**读者熟悉的现实例子，不抠细节、不堆第二个例子。
- 书里原话用双引号引出来，下面用大白话解释它在说什么、解决了什么。

### ④ 对读者的核心价值
- 今天为什么还要读、能拿走什么具体方法/思维、能纠什么误区。
- 可附一句"局限"收尾（如"写于 X 年，后来的 XX 它没涉及，但讲清了底层逻辑，当入门书读"），**收尾要顺**，禁"当作底层思路读"这类突兀硬造词——用"讲清楚了…的底层逻辑，当作理解…的入门书读"即可。

## 二、各书灵活结构示例（不要定死）

| 书类型 | 背景块侧重 | 核心内容块结构 | 注意 |
|---|---|---|---|
| 经济学/社科（国富论） | 旧观念 + 现实恶果 | 问题→解法 / 概念树 | 案例用生活物价、工厂 |
| 方法论/自助类 | 读者常踩的坑 | 问题→步骤 | 步骤用具体动作，禁"要学会思考"空话 |
| 小说/传记 | 时代背景 + 人物处境 | 人物动机 vs 时代 / 时间线 | 主线讲清"他为何这么做" |
| 科学/科普 | 旧理论的解释盲区 | 现象→机制→意义 | 用比喻要谨慎，机制直说 |

> 核心原则：**四块内容必出现，呈现顺序与拆法随书调整**。用户若说"按国富论那版做"，则默认用"背景对比框 + 问题→解法 + 概念树"组合。

## 三、语言禁忌词表（写到即改）

**抽象/端着词（禁用或替换）：**
增进福祉、托起整体、底层框架、民生困境、撬动认知、自发出清、认知盲区（除非原文）、殊途同归、一以贯之、归根结底（滥用）、赋能、闭环（滥用）、范式、底层逻辑（可用，但别每句挂）、信息差、心智、认知升级。

**AI 造词 / 拟人比喻（绝对禁用）：**
财富"长出来"、动力"锁死在土地里"、把束缚"解开"、经济"卡在坑里爬不出"、看窄了财富来源、焊死认知、出厂设置、自动挡（比喻思考）。→ 抽象概念不用具象动词、不生命化、不造动宾，能直说机制就直说 + 真实例子。

**碎句与断句（强制避免）：**
- 禁用"标签：词"当句子，如"财富的来源：分工""价值：劳动"。必须写成完整判断句："财富来源于社会分工""劳动决定价值""财富增长来源于资本积累"。
- 禁用超短句堆叠。每句必须有主语、谓语、结论，读完不用读者自己补主语。❌ "国民财富要增长。关键是分工更细。生产效率更高。" → ✅ "国民财富要增长，就要让劳动分工更细，这样生产效率才会更高。"
- 举例必须说完整因果，不能只抛例子。❌ "扣针工厂很出名：一人日产不到 20 枚，拆成 18 道工序后日产两千多枚。" → ✅ "书里举了一个扣针工厂的例子：一个人从头到尾做，一天生产不到 20 枚；但是拆成 18 道工序之后，每个人只需要负责其中一道，一人一天就能生产两千多枚。"
- 禁用默认读者已知的话，如"很出名""众所周知""不用多说"。
- 尽量不用"卷一/卷二/第一章/第二章"这类需要前置知识的指称，直接说内容；如果必须用，先说明"书中第一部分讲的是…"。

**连接词必须显式出现（自检）：** 每段至少出现 所以 / 但是 / 而不是 / 比如 / 原因是 / 结果是 / 也就是说 / 于是 / 偏偏。写完朗读一遍，"卡、跳、断"的地方必须补连接词。

**不刻意精简、保留原话连贯（硬律 · 最高优先级之一）：** 卡片是持续复盘/补充的活文档，不是论文摘要。这条针对的是最常见的翻车点——把用户已经梳理通顺的内容压成断句。

- **已经梳理好的内容，禁止压缩成断句。** 用户提供的公众号文章、口述、读书笔记、自己整理的文档，凡是已经直白、连贯、通顺的，一律直接引用或只做最小改写（去掉个别口语重复、把长句断点修顺即可），**绝不能删主语、删连接词、删自然语气去追求"简洁"**。压成"标签：词"或超短句堆叠（如"成功靠积累和放大（量变到质变）"），读起来每个字都懂、但前后断裂、连贯性极差，这恰恰是禁止的。
- **可以简洁，但不能断句化。** 简洁 = 去掉水词、不重复铺垫；断句化 = 把本来有逻辑承接的一整段话拆成互不连属的短句。前者允许，后者严禁。判断标准：朗读一遍，如果中间要自己补主语、补"所以/但是"才接得上，就是断句化了，必须还原成完整判断句。
- **关键承接词是连贯的核心，不能删：** "结果就是…""所以…""也就是说…""但是…""比如…"这些词不是废话，是逻辑链条的关节。保留它们。
- **没梳理好的部分，可以基于理解补写：** 用户没给到、或只点到概念名的地方，由你按作者原意补写逻辑+例子，没问题；但凡用户已经给了顺畅表达的，就尊重原话、别重写。

> 一句话记住：**用户写顺的，原样用；没写的，你补逻辑；谁都别压成碎句。**

**网页卡片必须结构化呈现，禁止做成文档式大段 prose（新增硬律）：**
- 知识卡片做成网页后，阅读场景变了——用户要"一眼抓到结构"，而不是"读完整段才懂"。所以核心内容必须模块化、层级化、可视化，不能像飞书/公众号文档那样堆大段文字。
- **每个概念模块的固定结构**：
 - 顶部：编号 + 概念名 + 一句话定义（一句大白话点透）。
 - **标题下灰字（cone）不要和正文里的「一句话先分清/一句话定义」或展开模块里的「定义」行重复，也不要写过渡废话**。cone 的作用是**点出核心对比/核心问题**，如"社会欠条 vs 睡着赚钱的资产"；不能写成"先分清这两个词，后面才不会串味儿"——正文下面已经区分了，这种铺垫纯属废话，删掉。
 - 中间：核心逻辑用**对比框**、**编号列表**、**关键词标签**、**公式/流程**呈现，不要写成连续 prose。
 - 底部：一个具体例子或故事框，把抽象概念落地。
- **图示只承载「简短示意」，完整逻辑必须交给下方 prose（新增硬律）**：
 - 概念卡 `.cdesc`、对比框 `.vd` 只写一句话核心判断或短标签，**不展开例子、不塞完整因果链、不堆解释**。图的任务是让人一眼知道"这个概念在说什么"。
 - 例子、完整因果链、"为什么"的解释，全部放到图示下方的 prose 里写。
 - 如果图里已经用某个例子做了示意，下方 prose 不要再复述这个例子，而是讲它背后的**逻辑**（原因、机制、后果）。
 - 后续补充新观点、新例子、新修正时，**优先往 prose 或独立模块里加**，不要往图里塞。图是骨架，prose 是血肉；骨架不能越画越满，否则血肉就没地方长。
- **允许的信息密度**：一句定义 + 3–5 个要点/标签 + 一个例子。禁止一个概念下出现超过 3 行的连续 prose 段落。
- **用户已梳理好的原文也要重新结构化**：不是把原文大段贴进网页，而是保留原话意思，拆成"对比框/列表/标签/例子"的网页结构。原话的连贯性由 md 镜像完整保留，网页卡片负责"结构化呈现"。
- **文档里已有明确对照关系的内容，卡片里必须显式用对比框 / 编号列表 / 关键词标签展开，不能只列一句话**。比如文档里有「穷人思维 vs 富人思维」「消费 vs 投资」「劳动性/投资组合/被动收入」「豪车悖论」等多层对照，卡片里就要做成左右对比框 + 三类收入编号列表 + 豪车悖论关键词框，不能压成一句"富人思维是把劳动收入转成被动收入资产"。
- **参考结构**：层级标题 + 数字编号 + "旧认知 vs 正解"对比 + 关键词标签 + 一句话例子。短视频知识图文（如巴菲豆风格）就是这种结构。
- 判断标准：截图后看网页，能否在 3 秒内看出这个概念有几层、每层核心词是什么、跟谁对比、例子是什么。看不出，就继续拆。
- **一处只加一次，避免过度重复**：用户让"补一句话/加一个观点"时，先检查全页是否已有类似表达。如果已有，只替换或扩展最该出现的位置（通常是展开正文），不能在顶部小卡、cone、展开模块、例子里各加一遍。比如"世界上没有一夜暴富的神话"只需出现在复利展开模块的「警惕」段，不必同时写进顶部小卡的 cdesc。
- **一个概念卡只干一件事**：概念卡只承载书中该概念本身（定义 + 本质 + 对比 + 例子）。衍生的生活应用、跨书联想、个人延伸必须放到「核心价值」「局限」「跨书关联」等独立模块，不能为了"内容丰富"把消费/投资/收入类型等衍生主题塞进「财富≠金钱」这类概念卡里。一张卡多重主题，读者会 confused。
- **禁止混入非本书内容（跨书关联请放 INDEX）**：单书卡片只聚焦这本书讲什么。用户读其他书（如《金钱心理学》《富爸爸穷爸爸》）汇总的观点，如果跟本书不是强相关，不要塞进正文；要建立跨书关系，请写到 `INDEX.md` 的"概念跨书关联"或卡片末尾独立的"跨书关联"小节，而不是把豪车悖论、收入三类等外部概念混进《纳瓦尔宝典》的某张概念卡里。
- **跨书关联必须基于具体概念，不能硬挂书名**：`《书名》.md` 的 `related_books` 不要写成 `[国富论, 金钱心理学, 富爸爸穷爸爸]` 这种只有书名的列表，必须写成带关联说明的键值对，点清"跟本书哪个概念对应、角度差异在哪"。例如：
 ```yaml
 related_books:
 - 国富论: "财富的本质：国富论从国家视角拆金钱≠财富，纳瓦尔从个人视角拆金钱≠财富+资产所有权"
 - 金钱心理学: "时间资产：真正的财富自由是能掌控自己的时间（纳瓦尔卡片直接引用）"
 ```
 弱相关或未来才收录的书不要硬塞；可在注释里标注"待后续收录后再补"。
- **`INDEX.md` 的跨书关联要分层**：不要所有关联都堆在一个列表里。拆成「强相关」（书中明确对应的概念，如财富本质、时间资产）和「可延伸关联」（角度相通但不强行等同，如提供价值、钱怎么用、系统性框架），让读者一眼看出哪些是真对应、哪些是形态类比。
- **同一层级条目必须统一编号，不能前面编号、中间缺号**：如果一组核心价值/要点用了编号列表（①②③④⑤），那么每个条目都要在编号容器里，不能因为某个条目需要展开对比框就把它抽成无编号的子标题。正确做法：给每个条目一个带编号的卡片/容器，内部再嵌套 `.vs` 对比框、`.levels` 编号列表或 `.tags` 关键词标签。确保读者一眼看出这是第几个点、和前后是什么关系。

**禁止强行造 AI 味金句（新增硬律）：**
- 不编造书中没有的对仗式、比喻式"金句"来"升华"，如"金钱只是财富的衣服，劳动才是财富的血液""人人想赚钱，最后却喂饱了所有人"。这种 AI 自己捏出来的格言，人味儿太淡，必须删。
- 书中原话才加双引号；没有原话支撑的排比句、对偶句、强行拟人，一律不写。
- 想强调一个观点，靠**一个具体例子**或一句**大白话**说清，不要把观点包装成格言。

**标题与标签必须完整（新增）：**
- 章节标题禁用缩略或省略。不能为了"看起来简洁"删掉主语、谓语或关键动词。❌ "四 · 斯密的核心主张：他怎么破的" → ✅ "四 · 斯密的核心主张"；❌ "只认金银是财富" → ✅ "认为金银就是财富"；❌ "只有土地和农业才创造财富" → ✅ "认为只有土地和农业才能创造财富"。
- 概念标签同样要写完整判断句，不能只抛关键词。❌ "财富来源：分工" → ✅ "财富来源于社会分工"；❌ "市场：自由运行" → ✅ "市场可以自由运行，但也有局限性"。

**配图不要写成文字（新增）：**
- 图本身就够说明的，不要额外加一句"每个节点下面都配了一张示意图""上图解释了…"这类自说自话的解释句。写了图，就别再说一遍。
- 如果正文和图重复，优先保留图，正文删到只剩一句点睛。

**标题下灰字（sec-sub）禁止人为折行（新增）：**
- `.sec-sub` 是章节标题下的解释/钩子句，**不能加 `max-width`**。加了 max-width 会让明明能一行显示完的句子被强制折成两三行，版面碎、阅读卡。
- 统一用 `font-size:22px`、容器宽度自适应，只有句子真正长到超出页面宽度时才自然换行。
- 自检：凡是章节副标题出现"一行明明能写完，却被截断"的情况，先检查 `.sec-sub` 是否被 `max-width` 限宽。

**颜色必须清晰可读（新增）：**
- 旧观念、次要模块不要用浅褐色（如 `#9A8C7D`），导出长图后容易发虚。统一用深棕 `#6A6058` 或红色 `#E0432E` 描边/文字，确保印刷、手机、公众号三端都清晰。
- 浅色只作大面积背景（`--paper`），不用来承载小字号文字。

**图示与文字必须同频（新增）：**
- 概念图中的对比项要用同一套逻辑顺序描述。如「水：有用·便宜」对应「钻石：用处小·贵」，保持"用处→价格"的对称，不能写成「钻石：贵·用处小」。
- 箭头/流程图必须能讲清机制，避免抽象循环。如「看不见的手」应画成：人人自利 → 价格涨落 → 资源分配 → 社会福利增加，让读者一眼看懂因果链。
- 图示内文字优先分两行、加大字号，确保导出长图后不截断。
- **标题、标签、图示三者必须一致**：卡片标题写「杠杆（4种）」，标签就不能是「人生支点的放大器」，图里更不能画「支点你」。不同概念（如杠杆 vs 支点）必须分开，不能为了套图而混用。
- **复利/指数曲线要画出真形态**：前期必须长时间贴近横轴（平缓），后期才陡峭上扬，不能画成近似 45° 的斜线。

**其他：** 书里原话必须双引号；禁"这句话被反复高亮""用户不理解"这类莫名其妙插入语；同一事实只在一处讲透（一信息一位置）。

**小红书多图拆分（新增）：**
- 如需直接发布到小红书，把长图拆成 **2-4 张 3:4 竖图**（宽:高 = 3:4，如 1080×1440，2x 导出 2160×2880）。不要整段内容塞成一张超长图，也不要用横版图。
- **去掉顶部 tab/导航条**：小红书没有网页导航，顶部只保留书名/章节名/页码。各章节的概念小图、图标要随正文自然分布到对应图片里，不要集中在某一页。
- **每图自洽**：每张竖图都要有独立的章节标题和可读懂的内容，用户单独刷到任何一张都能get到这一段在讲什么。
- **字号必须手机可读**：标题 ≥36px，正文 ≥22px，卡片说明 ≥18px；浅灰字 ≥18px。拆图是为了手机阅读，不要为了塞内容把字压小。**字号、内容完整、单页不溢出冲突时，优先保内容和可读，宁可加页也不硬压字号或删实质灰字。**
- **删冗余，保实质灰字**：删除的是重复铺垫和自说自话的图注，例如「18 世纪欧洲各国追求的强国之策，反而让老百姓越过越差」「两套观念，一个只认钱、一个只认地」；但「第一/第二」下面的具体说明、概念卡解释、价值卡描述、引用白话解释等**有信息量的灰字必须保留**，不能一刀切全删。
- **卡片收紧不留空**：卡片高度按内容自适应，不要为了让排版「对齐」而预留大段空白。左右对比卡、概念卡紧凑排布。
- **霞鹜文楷不用伪粗体**：霞鹜文楷只有 Regular 一个字重，CSS 里写 `font-weight: 700` 会让浏览器强行合成粗体，某些字会异常加粗、颜色变深。标题和强调靠字号 + 颜色分层，整页统一 `font-weight: 400`。
- **SVG 文字防漂移**：手写体 SVG 文字在 Ardot 等编辑器里容易错位。建议用 HTML + CSS + SVG 直接画好，再用 Puppeteer/Chrome 导出 PNG，坐标更稳。导出前禁用缓存、等待字体加载或做好 fallback，同一套 CSS 连跑两遍验证，避免字体未加载造成截断或漂移。
- **SVG 节点大小一致、颜色克制**：流程图/概念图里同类节点必须一样大，不要某个框突然变窄或变形；同一流程的节点尽量用一种主色，避免为区分而硬换颜色。
- **母版同步**：拆图里的样式改动（如「资源分配」框等宽同色、霞鹜文楷用 Regular）要及时回写长图母版，避免下次生成回到旧样式。
- **长图母版字号也要 PC 可读**：母版不是只给手机看，正文建议 ≥22–25px、章节标题 ≥34–40px、概念卡说明 ≥18px。按拆图版的放大逻辑整体上调一档。**但顶部 Hero（书名、作者、核心问题、tab 导航）不要同比例放大**，避免 tab 换行、头重脚轻；书名回到原来档位，核心问题保持醒目即可，把放大预算留给正文内容。
- 拆分时优先把「核心内容」的概念卡均匀分到 2 张图，避免最后一张太空、第二张太挤；核心价值单独放最后一张（拆图不保留「局限」模块，那是长图母版才有的）。**分块不是死的**：若按「前半/后半」分导致某页太空或溢出，可动态调整，把价值模块挪到合适页面，让每图饱满且不截断。

## 四、速读模式（只给书名时，调微信读书取真实重点）

接口网关 `https://i.weread.qq.com/api/agent/gateway`，POST，Header `Authorization: Bearer $WEREAD_API_KEY`，Body 平铺 `{"api_name":..., "skill_version":"1.0.4", ...}`。详细字段见 `weread-skills` skill。流程：

1. `/store/search` → 书名解析出 `bookId`（返回 V3 嵌套 `results[].books[].bookInfo`）。
2. `/book/info` → `title/author/intro/newRating/newRatingCount/publishTime`，喂"定位"与"值不值得读"。
3. `/book/chapterinfo` → 真实目录 `chapters[].{chapterUid,chapterIdx,title,level,wordCount}`；**章号/层级必须来自这里**，禁凭记忆。
4. `/book/bestbookmarks` → 全站热门划线 `items[].{markText,totalCount,chapterUid}`（按 `totalCount` 排序前 20）。这是"核心观点/最狠话"的真实燃料；并映射到 `chapterinfo` 的 `title` 标出出自哪章。
5. `/review/list` → 点评（差评预警用 `reviewListType:2`）。

**铁律：** bestbookmarks 服务端固定只返前 20 条，不够用 `/book/info` 简介 + `/review/list` 补，**严禁谎称"全书重点都在这 20 条"**；划线、评分、差评都必须基于真实返回，拿不准明说"公开数据有限"。

## 五、交付自检清单

- [ ] 顶部有书名 + 作者·年 + 全称 + 一行红字核心问题
- [ ] 四块内容齐全（定位 / 背景 / 核心内容 / 核心价值）
- [ ] 语言大白话，无禁忌词，每段连接词到位，朗读顺
- [ ] 用户已梳理好的内容未被压成断句（可简洁，不可碎句化；关键承接词保留）
- [ ] 引用原话有双引号，解释大白话
- [ ] 概念树/箭头沉底不穿框，节点只写概念名+短标签（具体解释在下方）
- [ ] 配色为暖红 #E0432E 套，无渐变/阴影/emoji
- [ ] 章号/划线若来自微信读书，均为真实返回
- [ ] 浏览器打开正常，Tab 吸顶高亮；**内容默认可见**，滚动时无整段空白断层
- [ ] 导出长图时，红色高亮 Tab 落在「核心内容」节（读者重点），**不是**主张/破局节（国富论即 `#s5`）
- [ ] 如用于小红书发布，已按 3:4 竖图拆成 2-4 张，无顶部导航条，概念图/图标随文分布
- [ ] 网页版核心内容不是大段 prose，而是模块化/层级化/有对比框/关键词标签/编号的结构化呈现
- [ ] 卡片是「重构」不是「搬运」：素材被重新组织成网页结构，截图 3 秒能说出每概念几层/核心词/对比/例子（非文档态）
- [ ] 凡有旧认知 vs 新认知 / A vs B / 前 vs 后 的对照，都用了对比框，且两栏同结构、点出了差异关键
- [ ] 「你以为 vs 真相」对比框：左栏只放单一错觉、右栏推翻同一前提的结论，没有把真相偷塞进左栏、也没有左右各讲一套不相干因果（否则自相矛盾）
- [ ] 连贯不跳：句子级连接词到位；**板块之间有承上启下**，不会"咔"一下跳到新逻辑（朗读无断层、新概念有铺垫）
